# 微信小程序方案与流程

> 目标：把「考研英语真题题库」做成微信小程序。本文档是可行性分析、技术路线对比和完整流程，供决策后直接执行。

## 一、先泼冷水：三个硬约束

| 约束 | 对本应用的影响 | 结论 |
|---|---|---|
| **个人主体小程序没有 web-view 权限**（仅企业主体可用，且目标域名必须 ICP 备案；`github.io` 无备案） | 最省事的"套壳网页"路线直接封死 | ❌ web-view 方案不可行 |
| **小程序无法运行 DOM 应用**（无 document/IndexedDB/Selection API） | React 网页版代码不能直接复用；**选中文字加批注/查词**依赖的 Selection API 小程序不存在 | UI 与交互层必须重写，批注交互需降级设计 |
| **本地存储上限 10MB**，代码包主包 2MB / 总包 30MB（需分包） | 44 套试卷 JSON 约 8MB + 词典 1MB，塞本地存储必爆 | 内容按需下载（wx.request 拉远端 JSON 缓存到本地文件系统，小程序文件系统无硬上限） |

## 二、可行路线对比

| 路线 | 做法 | 工作量 | 体验 | 备注 |
|---|---|---|---|---|
| A. web-view 套壳 | 小程序里嵌线上网址 | 1 天 | 完整 | ❌ 个人主体无权限 + 域名无备案，**放弃** |
| **B. Taro 移植（推荐）** | 用 Taro（React 语法，一套代码编小程序+H5）重写 UI 层，复用现有 `lib/` 逻辑层（text.ts/answers 思路/logger 思路）与 `content/` 数据 | 5–8 天 | 接近原生 | 交互降级见下节 |
| C. 原生小程序重写 | WXML/WXSS 全手写 | 8–12 天 | 原生 | 与 B 相比无优势 |
| D. 只做"轻版"小程序 | 只做做题+解析（无批注/无选词），数据云端拉取 | 2–3 天 | 功能阉割 | 快速上线的折中 |

**推荐 B（Taro）**，理由：React 语法与现有代码同构、`lib/` 纯逻辑层（分句/词形还原/SRS/判分）可几乎原样复用、还能顺带编译出 H5。

## 三、Taro 方案设计要点

### 交互降级（小程序无 Selection API）

| 原交互 | 小程序替代方案 |
|---|---|
| 拖选文字 → 查词/加单词本/批注 | **点词交互**：文章按词渲染为可点击节点（rich-text 或自定义组件），点词弹释义卡（查词/加单词本/批注一样不少） |
| 长按选中（移动端） | 同上，点词天然适配触屏 |
| 划线句翻译 | 原样支持（整块渲染） |
| 批注锚定 | 按词索引锚定（与现有 word-offset 方案一致，反而更简单） |

### 架构

```
小程序 (Taro)
├── pages: 首页(卷种tab)/试卷页(做题)/单词本/复习/错题/我的
├── 数据层: content.json 按需下载缓存(wx.getFileSystemManager) + 用户数据(wx.Storage)
│          → 封装成与 web 版 db.ts 同构的 repository 接口，逻辑层零改动
├── lib/（直接复用）: text.ts 分句/lemmatize/SRS、判分逻辑、logger 结构
└── AI 诊断: 导出 JSON → 微信"复制/转发给文件传输助手"（小程序无法起 HTTP 服务，
   AI 接口仅桌面版保留）
```

### 内容分发

44 套 JSON 打包到远端（两个选择）：
1. **GitHub Pages 直接用**（`afogsheep.github.io/kaoyan-english/content/...`）——零成本，但小程序"request 合法域名"必须是 **https + ICP 备案域名**，github.io 不满足 ❌（开发时可勾"不校验域名"，**正式上线不行**）
2. **需一个备案域名**（推荐）：OSS/COS/云开发静态托管均可，成本 ≈ 几元/月。云开发（TCB）免备案？——云开发默认域名仅开发期可用，正式也要备案域名。
   → **结论：正式上线必须有一个 ICP 备案的 https 域名**（这是小程序路线绕不开的前提，通常借轻量服务器+备案 1–2 周）

## 四、完整流程（谁做什么）

### 第 1 步：注册小程序账号（你，10 分钟）
- mp.weixin.qq.com → 立即注册 → 小程序 → 个人主体（免费，需邮箱+身份证+微信扫码）
- 拿到 **AppID**（设置 → 基本设置）

### 第 2 步：域名与备案（你，1–3 周，可与第 3 步并行）
- 买一台轻量云服务器或对象存储 + 一个域名（阿里云/腾讯云，¥50–100/年）
- 提交 ICP 备案（个人备案，管局审核 1–3 周）
- 备案通过后把 `content/` 44 个 JSON 传上去，https 可访问

### 第 3 步：Taro 工程开发（AI/我，5–8 天）
- 初始化 Taro（React + TS）→ 移植 pages → 复用 lib → 点词交互组件 → Storage 适配层
- 阶段验收：本地开发者工具里完整做题流程跑通

### 第 4 步：上传与审核（你+我，1–3 天审核期）
- 微信开发者工具导入工程（填 AppID）→ 上传代码 → mp 后台提交审核
- 类目选择：**教育 > 在线教育** 或 **工具 > 信息查询**（个人可选类目里通常"工具"最稳）
- 审核注意：真题内容标注"学习交流用途，侵删"；不含支付/社交裂变则易过
- 通过后发布 → 搜索名称/扫码使用

### 第 5 步：迭代
- 数据多端同步（可选）：加云开发，用 openid 打通小程序↔网页版数据（当前各端数据独立）

## 五、决策点（动手前需要你拍板）

1. **接受交互降级吗**：小程序里"划选文字"改为"点词"（功能保留，操作方式变化）——可接受则走 Taro 完整版；不能接受则小程序做 D 轻版（纯做题+解析）。
2. **愿意备案域名吗**：这是正式上线的硬前提（约 ¥100/年 + 1–3 周流程）。若不想备案，替代：**微信内直接打开 H5**（把线上网址发到微信/收藏，用内置浏览器+添加到桌面，体验接近小程序且零成本，已有）。
3. **先做哪个**：建议先 H5 微信内用起来（零成本），小程序作为正式发布的产品形态排期。

## 六、现状结论

- 手机上现在已经能用的路径（零额外成本）：浏览器/PWA、微信里打开线上版
- 小程序是"上架微信生态"的正式形态，总成本 = 你 10 分钟注册 + 备案 1–3 周 + ¥100/年 + AI 5–8 天开发
- 决策后说一声，Taro 工程随时可以开工
